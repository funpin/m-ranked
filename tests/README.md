# Какие тесты актуальны после смены стека

Рабочий интерфейс — Next.js, API — Spring, основная БД нового стека — PostgreSQL.
Наличие `legacy` или SQLite в имени теста само по себе не делает его устаревшим.

| Набор | Что проверяет |
| --- | --- |
| `frontend/tests/*.test.ts` | API-контракты, кеш, данные графиков, ошибки, формы и правила маршрутов |
| `frontend/tests/browser/` | Текущий Next.js: UUID-страницы, старые ссылки → 308, графики, клавиатура, история свыше 1000 замеров, роли и desktop/mobile |
| `backend/src/test/` | Spring API, PostgreSQL, Redis, CSV, транзакции, права, проекции и установка финальной схемы |
| `test_target_collectors*.py` | Сборщики PostgreSQL, сохранение импортированных UUID и исторического baseline |
| `test_migration_bridge*.py`, `test_migration_partition_postgres.py` | SQLite → PostgreSQL, точные рейтинги, возобновление после сбоя, ограничение подготовки партиций одной операцией на месяц в транзакции |
| `test_migration_status.py` | Серверная страница прогресса: подтверждённые checkpoint, привязка к снимку, паузы/перезапуски и прогноз времени |
| `test_reverse_sync*.py`, reconciliation, identity, archive | Сохранность данных, обратный перенос, история идентичности и архивы |
| `test_database.py`, `test_analytics.py`, `test_platform_analytics.py`, старые Python-сборщики | Используемый Python-код и совместимость исходных данных/формул; не тесты удалённого Python-интерфейса |
| `test_legacy_csv_contract.py`, `test_legacy_reference.py` | Явно подключённый внешний эталон CSV/миграции; он не подменяет текущий `app` |
| `test_operational_*`, backup, recovery, release gates | Linux-сценарии развёртывания, резервного копирования, прав и проверки артефактов |

## Запуск

Быстрый Python-прогон из корня: `rtk .venv/bin/python -m pytest -q`.
Тесты, которым нужны PostgreSQL/Redis, без DSN явно пропускаются. Серверные
shell-проверки используют Bash, GNU coreutils, GNU awk и `jq`; macOS не заменяет
Linux-прогон CI. Для Linux задайте `--basetemp` внутри доверенного рабочего
каталога: проверка provenance намеренно отвергает цепочку каталогов через `/tmp`.
Полный runner настраивает такой временный каталог самостоятельно. Песочница
также может запрещать локальные порты или сбрасывать setgid при `chmod` — это
ограничение окружения, а не основание ослаблять проверки прав.

Обязательный CI создаёт пустую Docker-БД напрямую из `final-schema.sql`,
проверяет единый schema contract и запускает Python/Java suites. Не подставляйте
production DSN. Старый SQLite cutover runner архивирован; см.
[migration/integration/README.md](../migration/integration/README.md).

Frontend: в каталоге `frontend/` выполните `rtk pnpm check` с Node 24 и
установленным Chromium (`rtk pnpm exec playwright install chromium`).

## Исторические проверки интерфейса

Строгое сравнение пикселей с прежним Python-интерфейсом не соответствует
согласованным UUID-маршрутам и общим графикам. Оно сохранено как отдельный
диагностический `--visual-only` / `pnpm test:visual`, с прежним порогом и
неизменёнными историческими отчётами. Его можно явно включить параметром
`legacy_pixel_audit` при ручном запуске GitHub Actions.

Обязательными остаются актуальные браузерные тесты, проверки данных в Spring/
PostgreSQL и `--semantic-only`: точные статусы всех карточек и их идентичность
после перехода по старым ссылкам, включая все страницы продолжения.

## Проверка GitHub Actions от 7 сентября 2026

Разобран [запуск № 5 на коммите 6e10107](https://github.com/funpin/m-ranked/actions/runs/34048246493).
В `canonical-integrity` четыре Python-теста падали из-за отсутствующей `.venv`
и размещения provenance-фикстур под общедоступным `/tmp`. Workflow теперь
создаёт `.venv`, а runner задаёт приватный временный каталог только pytest.
В `browser-parity` инспектор обращался к `analytics.comparison_metric_point`
через роль импорта без права чтения. Для инспекции временной БД теперь
используется отдельное подключение владельца в read-only транзакции.
Названия workflow и job ID сохранены; версии Actions обновлены до Node 24.

Локальная валидация изменений: полный интеграционный runner — 36 успешных
этапов, включая 136 Python-проверок с PostgreSQL без пропусков и 222 успешных
Spring-теста. Четыре служебных Spring-теста установки запускаются отдельными
этапами и пропускаются в общем наборе. Linux-прогон — 563 passed, 113 skipped
(проверки с отдельными DSN выполнялись интеграционными этапами); после него
новая проверка временного каталога прошла в отдельном наборе из четырёх тестов.
Frontend: 100 unit-тестов, 64 desktop/mobile browser-теста, lint, typecheck,
OpenAPI drift, production build и bundle budget прошли. Реальное сравнение
Next.js/Spring с эталоном прошло все 20 маршрутов со всеми страницами
продолжения; версия данных оставалась согласованной.

Это локальная проверка, не новый успешный запуск GitHub Actions. Полные
временные отчёты, тестовый Docker-образ и его кеш удалены после проверки
по просьбе пользователя. Команды воспроизведения приведены выше.
