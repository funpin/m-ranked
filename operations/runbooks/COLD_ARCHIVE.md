# Холодный архив — выведен из оборота (0063)

С октября 2026 года история замеров живёт в базе целиком: замеры моложе двух
суток — строками `ingest.publication_metric_snapshot`, старше — в упакованной
строке поста (`HISTORY_COMPACTION.md`). Упакованный месяц занимает в десятки
раз меньше, чем строки, поэтому выгрузка месяцев в Parquet/SQLite, копирование
на Сервер 1, закрытие месяца на запись и удаление партиций больше не нужны.

## Возврат месяцев, уже ушедших в архив

Месяцы в состоянии `cold` (`ops_and_admin.cold_archive_generation`) возвращаются
в базу один раз при переходе:

```bash
MAINTENANCE_DATABASE_URL=… PYTHONPATH=/opt/m-ranked/ops-libs \
  /opt/m-ranked/current/.venv/bin/python -m operations.cold_archive.restore 2026-07 2026-08
```

Для каждого поколения: SHA-256 файла сверяется с учётом, строки идут в базу
пачками через `ingest.restore_archived_snapshots` (строка встаёт ровно такой,
какой была, — номер исправления не пересчитывается), и каждая пачка тут же
сверяется побайтно по `canonical_record` (разница допустима только в
`ingested_xid`). Повторный запуск ничего не дублирует. Восстановленные строки
старые — их упакует служба упаковки.

Месяцы раньше 2026-07 не возвращаются: такие посты удаляются
(`operations/sql/purge-publications-before-2026-07.sql`).

После проверки файлы архива выводятся — сверщик хранилища удалит их на всех
серверах:

```sql
UPDATE ops_and_admin.storage_object SET retired_at = transaction_timestamp()
 WHERE kind IN ('archive_full', 'archive_browse') AND retired_at IS NULL;
```

## Что осталось в схеме

Таблицы поколений, ограждения месяцев и функции удаления партиции остаются
как история; код, который их вёл (выгрузка, просмотр, задания панели),
удалён. Поля `coldAfterDays` и `archiveNodes` политики хранения сохраняют
прежние значения и из панели не меняются.
