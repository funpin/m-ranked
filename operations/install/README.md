# Установщик

```bash
sudo python3 operations/install/install.py
```

Текстовый интерфейс без внешних зависимостей: его запускают по ssh на свежей
машине, где есть только системный Python.

## Что он делает

Заводит учётные записи и каталоги, генерирует секреты, собирает файлы
окружения из примеров в `operations/env/`, выпускает сертификаты переноса,
ставит юниты и drop-in'ы, проверяет их через `systemd-analyze verify`.

Три режима: профиль A целиком на одном сервере, и профиль B отдельно для
сервера сборщиков и для сервера web с аналитикой.

## Чего он не делает

Установщик не принимает решений за человека и не трогает то, что уже
настроено:

- не поднимает PostgreSQL и не применяет миграции;
- не собирает фронтенд;
- не правит firewall и DNS;
- не перевыпускает существующие секреты и не переписывает файлы окружения,
  которые уже есть — о каждом таком файле он говорит, что оставил как есть.

Список оставшегося он печатает в конце под конкретный режим.

## Сухой прогон

```bash
sudo python3 operations/install/install.py --dry-run
```

Показывает все действия, ничего не меняя. Полезно, чтобы увидеть состав
установки до первого запуска на боевой машине.

## Проверки окружения

Перед вопросами установщик проверяет права, systemd, Python, docker, Node,
диск, память, часовой пояс, openssl и занятость портов. Отмеченное `✗`
блокирует установку, `!` — предупреждение с объяснением, чем чинится.

Установщик ничего не доустанавливает сам: молчаливая установка пакетов на
чужом сервере — худший вид сюрприза.
