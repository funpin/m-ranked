# Маршрут обзора и фактические ворота M0

**27.09.2026 · `fixin` · только локально.** Этот журнал дополняет [текущую карту A–E](35_recheck_after_review_route_and_next_steps_2026-09-27.md). Production не менялся.

## Адреса и локальная проверка

В коде и ссылках интерфейса обзор находится на `/review`; он запрашивает `/api/v1/overview`. Эти адреса имеют разные назначения: публичная страница и структурированные данные. Контракт API уже не содержал `/api/v1/rating`, поэтому создавать новый псевдоним не требовалось. Редирект `/rating` на обзор удалён; этот адрес свободен для будущего отдельного продукта. Старые закладки `/?platform=…` продолжают вести на `/review`.

Проверено после пересборки только локального web-контейнера:

| Локальный запрос | Код |
|---|---:|
| `/review?platform=telegram` | 200 |
| `/rating?platform=telegram` | 404 |
| `/?platform=telegram` | 308 → `/review?platform=telegram` |
| `/api/v1/overview?platform=telegram&limit=20` | 200 |
| `/api/v1/rating` | 404 |

Для `all`, Telegram, VK, MAX и RuTube API локального офлайн-среза вернул по 20 элементов и `nextCursor`. Docker `pnpm build` с проверкой TypeScript прошёл; 10/10 браузерных fixture-тестов маршрутов и навигации прошли. В API, OpenAPI и пользовательских ссылках активного адреса `/rating` больше нет; остальные упоминания этого пути являются проверкой 404 или обозначают будущую страницу.

## Следующий шаг анализа: наблюдаемость перед M1

[SQL-отчёт M0](sql/m0_receipt_coverage.sql) теперь выводит все четыре платформы даже при пустой таблице. На локальном офлайн-срезе от 23.09 отчёт с `BEGIN READ ONLY` дал **0 успешных post-level reads и 0 соседних пар на каждой площадке**; таблица с индексами занимала 40 КБ. Это говорит об отсутствии новых receipts в данном срезе, а **не** об отсутствии роста постов.

Отчёт пока даёт только числитель наблюдений. Полный знаменатель должен фиксировать, какие посты действительно входили в opt-in когорту и были доступны для чтения в каждом окне, с успешностью цикла сбора; из одних сохранённых изменений метрик его вывести нельзя. Поэтому M1-оценка возраста/хвоста и признак «соседи не выросли» остаются вне сильного публичного решения. Следующее измерение — малая **живая локальная** когорта четырёх площадок, если есть доступы сборщиков: фактическое покрытие post×окно, точность/округление, коррекции, стоимость CPU/RSS/WAL/SSD. Затем fit/calibration/future holdout отдельно по платформе и возрасту, после чего M2 переносится из UI в backend.

**Важно для воспроизведения:** `infra/local/compose.env.example` указывает на демонстрационную базу с 10 постами; работающая локальная API-копия использует отдельный офлайн-срез с 70 802 постами. Указывать явное имя базы перед измерением и не смешивать результаты этих двух стендов. Ни один из них не является live production.
