## 26.09.2026 — новый этап реализации в `fixin`

По новому поручению владельца [план внедрения](20_research_conclusions_and_next_actions.md) начали выполнять локально. Ветка проверена: `fixin`. Удалённый production не меняли. Подготовлены выключенная по умолчанию малая когорта успешных post-level reads и миграция `0030`, офлайн исследовательская baseline M1 и извлечение соседнего контекста только из двух успешных read-событий. На временной поздней неделе 14d хвост `p_emp≤0,01` срабатывает у 7/207 MAX и 6/216 VK, то есть существенно чаще номинального 1%; для 24h fit/cal пригодных точек нет на всех четырёх платформах. Поэтому сильный публичный статус по этому прототипу не включать. Одним локальным запуском прошли 96 профильных unit-тестов; на чистой локальной БД миграция `0030` и integration 2/2 прошли после исправления cleanup-прав. Локальный production-style стенд `mranked-local` поднят на loopback, веб HTTP 200 и API ready `UP`; база без production-публикаций. Подробности, числа, воспроизведение и технические ворота — [21_fixin_implementation_and_m1_pilot.md](21_fixin_implementation_and_m1_pilot.md). К удалённому production не обращаться с записью.

## 26.09.2026 — предварительные наблюдения и решения

- 320-постовая детерминированная рамка содержит 22 записи `complete`, 73 `incomplete`, 225 `forced_incomplete`; выбор только complete был бы смещён. У 11 из 80 прочитанных постов первое реальное чтение позже суток. Это **подтверждённые факты данных**, не вывод об источнике трафика.
- В двух Telegram-кейсах поздний прирост реакций заметно быстрее локального прироста округлённых просмотров; в одном RuTube-кейсе за интервал ~13 ч просмотры выросли на 3986 при неизменных нулевых реакциях. Это **описательные кандидаты**, найденные после просмотра данных. Возможные причины не разделены; тест на новом периоде обязателен.
- Для всех H1–H9 в [реестре](04_hypotheses.md) отдельно записан статус: большинство ещё **не тестировалось**, H4/H8 имеют только пилотные наблюдения. Не выдавать отсутствие теста за опровержение, а большой описательный эффект — за p-value.
- Принят порядок M0 → M1 → M2 → M3: сначала аудит/условная baseline, затем дорогостоящие составные тесты, затем явная симуляция наблюдения. Он снижает риск приписать артефакт сборщика активности аудитории.

## Открытые измерения и решения будущего этапа

1. Проверить реакции по эмодзи и метаданные контента/CTA/закрепления/продвижения. Схема не равна реальной заполненности. Для `content_group_id` недельная проверка ниже уже показала нулевую заполненность; нужен другой механизм проверенного сопоставления.
2. Сформировать независимую случайную и обогащённую выборки с двумя слепыми ревьюерами; мои 16 меток не годятся для оценки точности. Получить будущий временной holdout после накопления достаточной истории.
3. Утвердить численный бюджет публичных ложных тревог **до** настройки порога и оценить его доверительную границу по каждой платформе/горизонту. Приоритет «меньше ложных тревог» согласован, число пока не задано.
4. Внедрение модели и интерфейса ручного управления — отдельная работа. Изменений production, схемы, API или frontend в этом исследовании нет.
