# Локальная демонстрация и синхронизация веток, 26.09.2026

## Что проверено

- В `fixin` объединена вся опубликованная ветка `feat/landing-and-docs` до `945a5d8`: главная, методология, справочник API и сопутствующие изменения. Конфликты страницы поста разрешены сохранением **обоих** механизмов: облегчённая первая выдача истории из ветки со-коммитера и контекстный анализ из [проверки №11342](23_local_neighbor_preview_2026-09-26.md). Конфликт прокси разрешён единым адресом публичного API для проверки ошибки и срока кэша.
- Уточнено сравнение ответов разных ревизий: старые окна допустимы для **предварительного** вывода, когда их конец как минимум на сутки раньше самого раннего `asOf` среди полученных ответов. Раньше требование разницы `asOf` не более 10 минут давало нестабильный статус из-за независимого кэширования списка и историй. Контрольный срез: список 18:02 UTC, истории 18:07–18:11 UTC при окнах 14–17 сентября. Это не доказывает неизменность исторических снимков при последующем backfill; для строгого воспроизведения нужен серверный общий срез или сохранённый набор входов.
- На обычной локальной карточке Telegram МФТИ №11342 (`/publications/26782437-05ec-5040-8313-3cb8fbf5eaff`) после перезагрузки браузер показывает **«Требует проверки»** вместо исходной «выраженной аномалии». Контекстная карточка содержит 3/3 окон с совместным ростом. На обеих шкалах истории появились пунктирные отметки времени новых постов: №11343–11344 и №11346. Просмотры включены на графике по умолчанию при наличии событий, пользовательский сохранённый выбор метрик остаётся главным. Отметка говорит о совпадении во времени и соседстве, не о причине.
- Новая главная `/` локально открывается с новым первым экраном и навигацией. В этом стенде общедоступные данные читаются через локальный read-only туннель; административный API использует только отдельную локальную базу. Продакшн, его база и текущие публичные сохранённые статусы не менялись.

## Проверки и границы

- `pnpm lint`, `pnpm typecheck`, локальный `pnpm build` и сборка Docker web прошли. Модульные проверки контекстного метода: 3/3. Общий набор фронтенд тестов на bundled macOS Node: 146/147, единственный сбой — нативный assertion процесса Node в `mobile-preflight.test.ts`, без обычного assertion из теста. Этот тест следует повторить в стандартном Linux CI; здесь он не использован как подтверждение поведения.
- Проверена **одна** карточка на реальных данных; это не оценка частоты ошибок и не калибровка сильного статуса. В третьем окне 17 сентября нет близкого нового поста, хотя старые соседи тоже выросли: остаток поста остаётся кандидатом для следующего анализа. Перенос просмотров Telegram возможен по [FAQ](https://telegram.org/faq_channels?setln=en), но индивидуальная причина роста без дополнительных наблюдений не установлена.
- Метод сейчас включён лишь в локальной демонстрации флагом `MRANKED_RESEARCH_PREVIEW=enabled`, загружает до шести соседних историй при открытии карточки и не пригоден для массового online-скоринга без кэширования и инкрементальных признаков. M0 receipts, калиброванный M1/M2 на всех четырёх площадках, межплощадочный анализ и независимая разметка остаются следующими этапами [карты](12_roadmap_status.md).

## Воспроизведение

Открыть локальную карточку №11342, раскрыть «Анализ динамики», увидеть 3/3 совместных окон и синие отметки новых постов над линиями просмотров. Статус метода — «Требует проверки». Исходные три сигнала остаются в свёрнутом разделе, а в публичном API сохраняется исходный результат. Для объяснения формулы, таблицы окон и научных ограничений см. [пилот](23_local_neighbor_preview_2026-09-26.md).
