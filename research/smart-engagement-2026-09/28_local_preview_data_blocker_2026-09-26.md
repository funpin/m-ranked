# Почему локальная карточка сейчас не показывает данные

Проверка 26.09.2026 после снимков владельца. Локальный Next.js отвечает и был успешно собран из ветки `fixin`; экран «Сервис временно недоступен» появляется при загрузке публикации из источника публичного API. Доступный read-only шлюз источника отвечает HTTP 502. Перезагрузка карточки не устраняет недоступность источника. Локальная одноразовая БД содержит **0 публикаций**, поэтому переключение страницы на неё не восстановит реальные графики.

Из production БД удалось выполнить только ограниченные запросы `BEGIN READ ONLY` для [дополнительных кейсов](27_additional_neighbor_cases_2026-09-26.md); это подтверждает наличие сохранённых измерений, но не работу публичного API. Production-службы, схема и данные не менялись.

Автоматическая проверка доступа отклонила попытку прямого туннеля к PostgreSQL: он открывал бы весь порт БД, шире необходимого публичного чтения, и мог бы дать доступ к записи при наличии других учётных данных. Этот путь **не используется и не должен обходиться косвенным запуском**. Его можно обсуждать только после явного пересмотра разрешений и ограничений доступа. Операционные адреса, порты и секреты здесь намеренно отсутствуют.

Для восстановления **живого** локального предпросмотра нужен доступный публичный API или другой заранее ограниченный сервис только на чтение. Отдельный офлайн-снимок выбранных реальных кейсов технически возможен, но его следует показывать с датой среза и не выдавать за текущие данные или за полную локальную копию production.
