# Политика состава зависимостей

Правило простое: в продуктовую среду попадает только то, что перечислено в
lock-файле с хешем, а решение «выпускать или чинить» принимается по
достижимости, а не по номеру CVE.

## Что чем закреплено

| Файл | Кто ставит | Чем проверяется |
| --- | --- | --- |
| `requirements/tooling.lock` | все образы и релиз | `pip install --require-hashes` |
| `requirements/api.lock` | образ API, релизный `.venv` | то же |
| `requirements/collector.lock` | образ коллекторов | то же, `--no-build-isolation` |
| `requirements/anomaly.lock` | образ поиска аномалий | то же |
| `requirements/pymax.txt` | отдельный слой сборки | полный коммит + sha256 колеса в журнале сборки и SBOM |
| `frontend/pnpm-lock.yaml` | фронтенд | `pnpm install --frozen-lockfile` |

`requirements/dev.txt` и `requirements.txt` — только разработка и CI. Задание
`supply-chain` отдельно проверяет, что ни pytest, ни Playwright, ни сканеры не
попали в SBOM продуктовых окружений.

Lock пересоздаётся целиком скриптом `operations/scripts/generate_python_lock.py`
под linux x86_64 и CPython 3.13 — под ту платформу, на которой собираются
образы. Ручная правка строки в lock приравнивается к отключению проверки.

## Пороги выпуска

| Условие | Действие |
| --- | --- |
| Уязвимость в каталоге CISA KEV и код достижим | выпуск блокируется, исправление в тот же день |
| Critical или High, исправление доступно, код достижим | блокируется, исправление до семи дней |
| Critical или High, код недостижим | не блокируется, запись в `security/vex.json` с обоснованием и сроком |
| Medium и ниже | плановое обновление, отдельная запись не требуется |

«Достижим» означает: пакет установлен в продуктовом окружении **и** уязвимый
путь вызывается кодом проекта. Оба условия проверяются вручную и записываются.

## Исключения

Исключение живёт только в `security/vex.json`, только с владельцем, причиной
недостижимости, датой окончания и ссылкой на тест, который сломается, если
недостижимость исчезнет. Просроченное исключение снова блокирует выпуск.
Широких исключений по пути или по правилу не бывает — ни в `.gitleaksignore`,
ни здесь.
