# Live-read performance gate — 2026-09-13

This is release evidence from the local restored `mranked_next` copy, not a
production SLO claim. The copy contains 7,492,177 publication snapshots and
13,220,721 reaction rows. PostgreSQL 18.6 ran on the developer machine; parallel
query was disabled so one query could not hide CPU cost behind extra workers.

`tests/test_live_query_budgets_postgres.py` runs the exact SQL used by every
public screen and `/manage` under `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`.
Comparison cohorts select the 25 entities with the most eligible publications
and set `includePartial=true`, the expensive supported path.

| Query group | Execution, ms | Shared blocks |
|---|---:|---:|
| Overview, all/30d | 66.1 | 74,792 |
| Rating entities | 8.4 | 19,632 |
| Rating publications | 6.1 | 8,033 |
| Detail/list/history/anomaly queries | 0.007–3.6 | 2–1,159 |
| Manage catalog | 99.2 | 86,556 |
| Manage accounts/status | 1.2–2.8 | 184–1,699 |
| Compare Telegram, 24h | 306.2 | 30,003 |
| Compare Telegram, 336h | 1,908.3 | 125,891 |
| Compare VK, 24h | 1,307.4 | 117,302 |
| Compare VK, 336h | 3,443.9 | 160,871 |
| Compare MAX, 24h | 2,743.1 | 126,830 |
| Compare Rutube, 24h | 328.9 | 28,601 |

The executable limits are 1,000 ms / 100,000 blocks for ordinary screen
queries, 4,000 ms / 220,000 blocks for 24-hour comparisons, and 5,000 ms /
260,000 blocks for 336-hour comparisons. These are developer-machine release
budgets. In particular, 1.3–3.4 second VK/MAX comparisons are honest current
latency, not evidence that a production 1-vCPU host meets an interactive SLO.

The complete Python suite also passed in a Linux container with a hard 15 GiB
cgroup limit (234 passed, 17 role-specific tests skipped). The complete frontend
gate passed under the same limit: 103 unit tests, 102 Playwright scenarios,
production build and every bundle budget.
