# Вкладка «Рейтинг»: прогноз М-Рейтинга по соцсетям и каркас «Нашего рейтинга»

Дата: 2026-10-16. Статус: дизайн согласован в чате по разделам, ждёт ревью
спека. Выкатка на прод — только после явного «делай» владельца.

## Зачем

Владелец хочет до публикации официального М-Рейтинга Минобрнауки
(m-rating.ru) видеть, какое место вуз получит по соцсетям, — по нашим
данным отслеживания. Второй раздел вкладки — собственный рейтинг; его
методику решим позже, сейчас нужен каркас и место под методику.

Отдельный вопрос (пункт A задачи): вуз бывает в топ-10 общего рейтинга по
соцсетям, не входя в топ-10 ни VK, ни MAX, ни Rutube. Расчёт должен
воспроизводить это, а не «исправлять».

## Что известно о формуле (подбор 15.10 на сентябре 2026)

- Точно, до округления: `соцсети = 0.4·MAX + 0.3·VK + 0.3·Rutube`; Telegram
  с августа 2026 — `null`. Сводный рейтинг дополнительно берёт СМИ, сайт и
  повестку МОН, их мы не собираем.
- VK и MAX: балл площадки — среднее трёх подбаллов, каждый
  `100·ln(x/низ)/ln(верх/низ)`, обрезанный в 0–100:
  публикации за месяц 20 → 100; средние просмотры публикации / контингент —
  VK 0.1 → 3, MAX 0.03 → 0.5; ERV = (реакции+комментарии+репосты)/просмотры —
  VK 0.5 % → 4 %, MAX 0.5 % → 10 %. LOO-CV R² 0.87.
- Rutube: меньше 5 видео за месяц — 0; выше порога ≈ `12·ln(видео)`;
  «глубину просмотров» мы не собираем (R² ≈ 0.41). Официальный рейтинг
  считает видео по дате загрузки (`created_ts`), мы храним только
  `publication_ts`.

## Пункт A: почему СКФУ в топ-10 без топ-10 на площадках

Проверено на официальных данных сентября по всем 233 вузам: СКФУ —
8-е место по соцсетям при 27-м в MAX, 38-м в VK и 13-м в Rutube;
Байкальский ГУ — 9-е при 11/39/27. Это свойство формулы: соцсети — взвешенная
сумма **баллов**, а не мест. Ровно сильный на трёх площадках вуз обходит
лидеров одной площадки, слабых на остальных. Сильно решает Rutube: баллы там
от 0 до 90 при медиане ≈ 19, у 83 вузов 0 (порог видео), поэтому 48.5 балла
в Rutube дают большую прибавку при весе 0.3.

Следствия для расчёта:

1. Сначала балл каждой площадки на официальной шкале 0–100, затем сумма с
   весами 0.4/0.3/0.3, и только потом места. Выводить общее место из мест
   на площадках или их суммы нельзя.
2. Место официально — среди всех 233 вузов, а отслеживаем мы 75 (с кодом
   m-rating). Остальные 158 получают баллы последнего опубликованного месяца
   (решение владельца).

## Бэктест (16.10, локальная копия прода на 13.10)

75 вузов, места среди 233 (прочие — из предыдущего месяца). Сентябрь —
in-sample для порогов, честная оценка — август.

| Вариант | MAE соцсети, баллы (авг / сен) | Медиана ошибки места | ρ | Попадание в топ-20 |
|---|---|---|---|---|
| Место прошлого месяца | 7.5 / 5.6 | 30 / 16 | 0.62 / 0.83 | 9/19, 12/18 |
| **Формула по нашим метрикам** | **7.2 / 4.2** | **17 / 14.5** | **0.73 / 0.86** | **13/19, 15/18** |
| Формула + поправка на ошибку прошлого месяца | 17.5 / 6.1 | 32 / 15 | хуже | хуже |
| Формула + линейная перекалибровка на прошлом месяце | 8.5 / 5.0 | 27.5 / 22 | 0.55 / 0.85 | — |

Выводы: берём формулу без поправок. Баллы плотные: ±4 балла ≈ ±15 мест,
поэтому место показываем диапазоном. Нижневартовский ГУ в августе — 5.8
вместо 64.1: вуз добавлен в каталог 15.09, истории за август у нас нет —
отсюда проверка полноты (ниже). Rutube наверху занижен (ПНИПУ 57 вместо 70).

## Решения владельца (16.10)

- Места — среди всех 233, прочие 158 — из последнего опубликованного месяца.
- Период: текущий месяц — бегущая оценка с пометкой «месяц не закончен»;
  законченный, но не опубликованный — итоговый прогноз; после публикации —
  сравнение прогноза с фактом.
- Только соцсети (общий + MAX/VK/Rutube). Сводное место прошлого
  опубликованного месяца — справкой под таблицей, без прогноза.
- Вкладка «Рейтинг» — после «Сравнения», путь `/rating`, без параметра
  площадки.
- «Наш рейтинг»: каркас + набросок методики (статус «в разработке», открытые
  вопросы), пустой каркас таблицы; API отвечает «методики нет».
- Расчёт — ежедневным снимком в таблицы `rating.*`, а не на лету.
- График: разброс «прогноз против факта» для опубликованного месяца.
- Август–сентябрь рассчитать задним числом при выкатке, с пометкой
  «ретроспективный расчёт, не прогноз до публикации». Июнь–июль не считаем:
  истории VK/MAX за них почти нет (июль — VK у 38 из 75, MAX у 28), сравнение
  вышло бы искусственно хорошим на подменах (уточнение 16.10).
- Бегущая оценка незаконченного месяца: число публикаций экстраполируется
  на полный месяц (× дней в месяце / прошло дней), средние просмотры и ERV —
  только по постам старше 3 суток; до 7-го дня месяца оценка помечается
  «слишком рано» (решение 16.10).

## Не входит

СМИ, сайт, повестка и сводный прогноз; профиль вуза; методика «Нашего
рейтинга»; сбор `created_ts` Rutube (изменение сборщиков на Сервере 1 —
отдельная задача); перебор порогов (их правка — новая версия формулы).

## 1. Расчёт прогноза

**Состав.** 75 вузов с действующим кодом `m-rating`
(`catalog.institution_external_id`, `valid_to IS NULL`). Прочие
отслеживаемые вузы в официальном рейтинге не участвуют и в прогноз не входят.

**Метрики площадки за месяц** (границы месяца — по Москве; публикации без
`deleted_at`, аккаунты без `deleted_at`, сумма по всем аккаунтам вуза на
площадке):

- `posts` — число публикаций;
- `avg_views` — сумма просмотров / число публикаций с известными
  просмотрами (`analytics.publication_latest`), просмотры — накопленные к
  моменту снимка;
- `students` — контингент из `api/data/institution-student-counts.json`;
- `erv` — (реакции + комментарии + репосты) / просмотры.

**Балл площадки** (0–100):

- VK, MAX: `(sub(posts, 20, 100) + sub(avg_views/students, lo, hi) +
  sub(erv, elo, ehi)) / 3`, где `sub(x, a, b) = clip(100·ln(x/a)/ln(b/a), 0,
  100)`, `sub(0) = 0`; без контингента подбалл просмотров — 0 с пометкой.
- Rutube: `posts < 5 → 0`, иначе `m = min(100, 12·ln(posts))`; если
  официальный балл Rutube базового месяца больше 0 —
  `0.5·m + 0.5·официальный`, иначе `m`.
- Нет аккаунта на площадке — 0 (как в официальном рейтинге).

**Полнота данных.** Площадка вуза покрыта за месяц, если у каждого её
активного аккаунта `catalog.platform_account.created_at` не позже начала
месяца **или** самая ранняя собранная публикация аккаунта раньше начала
месяца (догрузка истории дошла до месяца целиком). Нижневартовский ГУ: VK
добавлен 15.09, самая ранняя публикация 02.09 — сентябрь не покрыт; Rutube
добавлен 15.09, история с 01.07 — покрыт. Непокрытая площадка получает
последний официальный балл с пометкой «нет полных данных — взят балл за
<месяц>».

**Соцсети и места.** `соцсети = 0.4·MAX + 0.3·VK + 0.3·Rutube`. Места по
каждой категории (соцсети, MAX, VK, Rutube) — среди 233: наши 75 с
прогнозными баллами плюс 158 прочих с баллами базового месяца (последнего
опубликованного, из `rating.official_import.evidence`). Равные баллы
упорядочиваются как в импорте официального рейтинга (балл ↓, название).

**Диапазон места.** Для каждой категории — типичная ошибка балла `e`
(MAE последнего опубликованного месяца с прогнозом; до первого такого месяца
— из бэктеста: соцсети 7, MAX 10, VK 9, Rutube 9). Диапазон — места,
которые вуз занял бы с баллом `балл − e` и `балл + e` при прочих баллах
неизменными.

**Rutube наверху.** Формула занижает каналы с большим числом видео. Смесь с
последним официальным баллом (вес 0.5) уменьшает MAE Rutube во всех трёх
проверенных месяцах: июль 8.6 → 7.5, август 8.9 → 8.3, сентябрь 8.3 → 5.9
(веса 0.75 и 0.25 хуже или так же). Она входит в версию 1 формулы.

**Незаконченный месяц.** `posts` всех площадок умножается на
`дней в месяце / прошло дней` (по Москве, прошедшие сутки включая текущие);
`avg_views` и `erv` считаются по постам, опубликованным не позже
`as_of − 3 суток` (если таких нет — по всем). Правило 3 суток применяется
ко всем снимкам: к моменту публикации официального месяца все посты зрелые.
До 7-го дня месяца у снимка `parameters.early = true`.

**Бэктест** — скрипт в репозитории: для каждого опубликованного месяца
печатает MAE баллов по категориям, медиану и 80-й перцентиль ошибки места,
ρ Спирмена, попадание в топ-20. Нужен, чтобы видеть, когда пороги уехали.

## 2. Хранение и ежедневное задание

**Формула как данные.** Миграция `0084`:

- строка `rating.formula_definition`: `formula_key =
  'm-rating-social-forecast'`, `version = 1`, `status = 'published'`,
  `definition` (jsonb) — пороги, веса, порог Rutube, часовой пояс месяца,
  типичные ошибки бэктеста; `source_hash` — sha256 канонического JSON;
- столбец `rating.rating_run.parameters jsonb NOT NULL DEFAULT '{}'`
  (базовый месяц, типичные ошибки, статус снимка, пометка ретроспективы);
- запись — через функции `SECURITY DEFINER` по образцу
  `ops_and_admin.import_official_rating`: `ops_and_admin.record_rating_forecast`
  (снимок целиком, замена снимка тех же суток, событие outbox с тегом
  `rating-forecast` для сброса кэша) и `ops_and_admin.finalize_rating_forecast`
  (пометка итогового, удаление промежуточных); `EXECUTE` — только
  `api_write_admin`. Прямых прав на `DELETE` никому не добавляется;
- чтение баллов всех 233 вузов базового месяца — функцией
  `rating.official_period_scores(period)` (`SECURITY DEFINER`, `EXECUTE` у
  `api_write_admin`): `rating.official_import` сейчас читает только
  `maintenance`; чтение снимков у `api_read` уже есть.

`rating.formula_component` и `rating.rating_component_result` не
используются: их `metric_key` не покрывает ERV и число публикаций, странице
они ничего не дают. Перебор порогов — новая версия формулы; старые снимки
остаются объяснимыми своей версией.

**Снимок** — строка `rating.rating_run` (`window_start/end` — месяц,
`as_of` — момент среза, `dataset_revision_id` — последняя ревизия на момент
расчёта, `input_hash` — sha256 входных агрегатов) и 75 строк
`rating.rating_result`: `score`/`rank` — соцсети и место среди 233;
`explanation` — по каждой площадке балл, место, диапазон, подбаллы, сырые
метрики, признак полноты и источник подмены; базовое официальное место.

**Статусы снимка** (в `parameters.status`): `running` — месяц идёт;
`final` — месяц закончен, официального нет; `published` — официальный месяц
вышел (снимок — последний до публикации, неизменен);
`retrospective` — расчёт задним числом.

**Задание** `api.tools.rating_forecast` + unit/timer по образцу
`m-ranked-target-official-rating` (тот же пользователь, учётные файлы и
ограничения, `CPUWeight=10`, `IOWeight=30`); запуск раз в сутки после
проверки официального рейтинга и до ночного дампа. Агрегаты читает пул
чтения, пишет `api_write_admin` одной транзакцией под advisory lock. Каждую
ночь считает текущий месяц и законченный неопубликованный. Повторный запуск в
те же сутки заменяет снимок этих суток. Когда официальный месяц появился,
последний снимок до публикации помечается итоговым, промежуточные снимки
этого месяца удаляются.

**Ретроспектива.** Режим задания `--retrospective 2026-08..2026-09`:
по одному снимку на месяц со статусом `retrospective`. Запускается разово
при выкатке с низким приоритетом.

**Объём.** На пике ≈ 2 снимка в сутки × 31 день × 75 строк ≈ 10 МБ; после
очистки — 75 строк на месяц. Новых кэшей и буферов нет.

## 3. API и страница

**API** (описывается в `contracts/openapi/m-ranked-v1.yaml`, клиент
генерируется; ответы через `serve`/ETag, как остальные публичные):

- `GET /api/v1/rating/forecast/months` — месяцы со снимком и статусом.
- `GET /api/v1/rating/forecast?month=YYYY-MM` — параметры снимка (срез,
  базовый месяц, версия формулы, типичные ошибки, статус) и 75 строк:
  по четырём категориям балл, место среди 233, диапазон, последнее
  официальное место, признак подмены; для `published`/`retrospective` — ещё
  фактические место и балл. Без `month` — текущий месяц. Нет снимка — 404.
- `GET /api/v1/rating/own` — `{status: "no_methodology", questions: [...]}`.

**Навигация.** Пункт «Рейтинг» после «Сравнения» в `frontend/lib/nav-links.ts`,
`platformless`.

**`/rating` — «Прогноз М-Рейтинга»:**

- шапка: переключатель месяца (по умолчанию текущий), статус («месяц не
  закончен, данные на 16.10» / «итоговый прогноз» / «опубликовано —
  сравнение с фактом» / «ретроспективный расчёт»), короткая оговорка (только
  соцсети; СМИ, сайт и повестка не прогнозируются);
- переключатель категории: Соцсети · MAX · VK · Rutube (по весу);
- таблица: прогнозное место с диапазоном, вуз, балл, изменение против
  последнего официального места, баллы площадок (во вкладке «Соцсети»);
  пометка неполных данных с пояснением; для опубликованного месяца — столбцы
  «прогноз / факт / ошибка»;
- для опубликованного и ретроспективного месяца — разброс «прогнозное место
  против фактического» (точка — вуз, диагональ — идеальный прогноз);
- под таблицей справкой — сводное место прошлого опубликованного месяца.
  Сейчас импорт официального рейтинга сводный балл не хранит; импорт
  начинает сохранять `consolidated` в `evidence`, и справка появляется с
  первого импорта после выкатки (октябрь, середина ноября); до этого строки
  нет;
- блок методики: формула, пороги, ограничения, ошибка бэктеста, ссылка на
  статью в «Методологии» (MDX в `frontend/content`).

**`/rating/own` — «Наш рейтинг»:** блок методики со статусом «в разработке»
и списком открытых вопросов, пустой каркас таблицы.

## 4. Проверка, замеры, выкатка

**Тесты (TDD):**

- чистый модуль расчёта (без базы): подбаллы и обрезка, порог Rutube,
  веса, места среди 233 с подменой, полнота, диапазон; отдельный тест на
  пункт A — ровно сильный вуз выше лидеров одной площадки;
- читатель агрегатов и задание на одноразовом Postgres: права под
  `SET ROLE api_read` / `api_write_admin`, один снимок в сутки,
  финализация, очистка, ретроспектива;
- маршруты API: ответы, 404, заглушка, соответствие контракту;
- фронтенд: пункт меню, оба раздела, переключатели, пометки, разброс только
  для опубликованного месяца; e2e на фикстуре.

**Замеры (AGENTS.md)** — на локальной копии прода: время и
`EXPLAIN ANALYZE` агрегации задания и читателя API (`jit = off`,
`random_page_cost = 1.1`), CPU и память задания, p50/p95 холодный/тёплый
`/rating` и до/после — `/review`, `/compare`. Ухудшение — стоп и цифры
владельцу.

**Выкатка (после «делай»):** миграция `0084` на базе Сервера 2, оверлей-релиз
API и web по процедуре релиза, новые unit/timer, разовая ретроспектива
август–сентябрь с низким приоритетом. Сервер 1 и сборщики не трогаем.

## Ограничения, о которых пишем на странице

- Наш контингент ≠ их «приведённый контингент без филиалов».
- Минимумы и максимумы по 233 вузам нам неизвестны: пороги подобраны на
  наших 75 и могут уезжать от месяца к месяцу.
- Просмотры растут после конца месяца; официальный срез — неизвестной даты.
- Rutube: нет «глубины просмотров» и даты загрузки видео.
- Источник иногда не учитывает канал (Орловский ГАУ, БГТУ им. Шухова — MAX
  0 при активных каналах): прогноз это не предсказывает.
