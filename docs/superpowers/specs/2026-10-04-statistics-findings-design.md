# /statistics → «Находки»: посты выше нормы

Дата: 2026-10-04. Статус: дизайн согласован, ждёт ревью спека.

## Цель и пользователь

Главный пользователь — SMM-специалист или аналитик вуза. Его задача: найти
посты, которые сработали заметно лучше обычного, понять, что это за пост, и
повторить удачный приём. Смотреть нужно и на свой вуз, и на «взлетевшие» посты
коллег.

## Границы страниц

Правило: единица анализа определяет страницу.

| Страница | Строка / точка | Вопрос |
|---|---|---|
| `/compare` | вуз | как вуз выглядит на фоне других по многим метрикам |
| `/accounts/[id]` | пост одного аккаунта, по хронологии | что публиковал аккаунт |
| `/publications/[id]` | один пост | история замеров и разбор аномалии |
| `/statistics` | пост среди многих аккаунтов | какие посты сработали выше нормы своего аккаунта |

На `/statistics` нет: рейтинга вузов и агрегатов по вузу (ERV вуза, медиана
вуза), хронологической ленты аккаунта, истории замеров, графиков и сводок
«что общего у лучших постов» (это `/compare`, «Время и форматы»).
`/compare` в рамках этой работы не меняется.

## Структура страницы

Адрес остаётся `/statistics`, пункт меню — «Статистика». Заголовок: «Находки:
посты выше нормы». Вкладки «Публикации / Вузы» удаляются.

**Режимы** (`ToggleGroup`):

1. **Все вузы** — лента постов выше нормы по всем аккаунтам.
2. **Мой вуз** — все посты выбранного вуза по всем его площадкам, без порогов
   отбора; сортировка по возрастанию показывает провалы. Вуз выбирается через
   `Combobox` и хранится в URL (`institution`) и в `localStorage` (только как
   удобство: чтение и запись в `try/catch`, страница работает без него).

**Группировка** (только «Все вузы»): «Списком» (по умолчанию) или «По вузам».
В группировке строка вуза содержит короткое название, площадки и «найдено N
постов выше нормы»; под ней 3 лучших поста и ссылка «все посты вуза →»,
переключающая в режим «Мой вуз» с этим вузом. Вузы упорядочены по индексу
лучшего поста; вузы без находок не показываются. Сводных метрик вуза нет.

**Фильтры.** В одну строку: режим (+ `Combobox` вуза в режиме «Мой вуз»),
площадка (Все / TG / ВК / MAX / RT), период (24 ч / 7 д / 30 д), сортировка.
В `Popover` «Фильтры» со счётчиком активных: тип публикации (множественный
выбор), группировка, поиск по номеру / URL / аккаунту. Период «3 ч» удаляется.

Сортировки: индекс по взаимодействиям (по умолчанию), индекс по просмотрам,
взаимодействия · 24 ч, просмотры · 24 ч, ERV · 24 ч, новые. Направление —
по убыванию / по возрастанию. Всё состояние — в URL.

## Метрика «индекс к норме»

```
индекс = значение поста на возрасте h ÷ норма аккаунта на возрасте h
```

- **Возраст h.** 24 ч, если точка есть в `analytics.publication_checkpoint`.
  Иначе — самая поздняя доступная из 12 / 6 / 3 / 1 ч; индекс помечается
  «предварительно, N ч». Значения после 24 ч в индекс не входят.
- **Взаимодействия** — реакции + комментарии + репосты по матрице
  `api/statistics_capabilities.py` (Telegram — с комментариями; MAX — только
  реакции). Отсутствующий поддерживаемый компонент даёт 0; если все
  поддерживаемые компоненты отсутствуют, взаимодействий нет (NULL).
- **Два индекса:** по взаимодействиям (основной, сортировка по умолчанию) и по
  просмотрам.
- **Норма аккаунта** — медиана значения на возрасте h по постам того же
  аккаунта, вышедшим за 90 дней до `as_of`, не считая сам пост. Из нормы
  исключаются посты с действующим уровнем аномалии 2–3.
- **Минимальная история:** не меньше 10 постов с точкой на возрасте h. Иначе
  индекс NULL («мало истории»), при сортировке по индексу — в конце.
- **Нижние ограничения знаменателя:** норма взаимодействий не меньше 5, норма
  просмотров не меньше 50.
- **Порог ленты «Все вузы»:** индекс по взаимодействиям ≥ 1,5 и не меньше 10
  взаимодействий на возрасте h. В режиме «Мой вуз» порогов нет.

Пороги (90 дней, 10 постов, 5 / 50, 1,5×, 10) — стартовые. До написания плана
они проверяются на проде запросом только на чтение (сколько постов проходит
по каждой площадке) и затем фиксируются в методологии.

Действующий уровень аномалии берётся так же, как на `/compare`:
`coalesce(post_anomaly_context_recheck.effective_level, post_anomaly_state.level)`.

## Правило по аномалиям

| Действующий уровень | В выдаче |
|---|---|
| 0 | показывается |
| 1 | показывается с пометкой «слабый сигнал» |
| 2–3 | исключается; под таблицей «Скрыто N постов с выраженной аномалией» со ссылкой на `/compare#anomalies` |
| 2–3, понижен ручной проверкой (recheck) | показывается по действующему уровню |
| не проанализирован | показывается с пометкой «не проверен» |

Если `ANOMALY_REPORT_VISIBLE=false`, фильтр не применяется, пометки не
показываются, в шапке `Alert`: «Проверка аномалий временно недоступна — посты
не отфильтрованы». Норма в этом случае всё равно считается без уровней 2–3:
флаг управляет показом, а не расчётом.

## Строка поста

Колонки: Пост · Индекс · Взаимодействия · 24 ч · Просмотры · 24 ч · ERV · 24 ч ·
ссылка на оригинал.

- **Пост:** короткое название вуза, площадка (в режиме «Все»), тип публикации
  (подписи из `typeName` в `frontend/lib/compare-dashboard.ts`), номер, день
  недели и время выхода по Москве. Не больше одного `Badge variant="outline"`
  с пометкой, по приоритету: «предварительно, N ч» → «слабый сигнал» →
  «не проверен».
- **Индекс:** единственный жирный акцент, формат `×4,2`; от 2× — цвет
  `primary`. `Tooltip`: норма аккаунта, индекс по просмотрам, размер выборки
  нормы. NULL → «—» с подсказкой «мало истории для нормы».
- **Взаимодействия:** одно число; `Tooltip` — разбивка по компонентам,
  поддерживаемым площадкой, и текущие накопленные значения.
- Клик по строке → `/publications/[id]`; ↗ → оригинал.
- Мобильная ширина — карточки: индекс крупно справа, три метрики снизу.
- Текст поста не показывается: в базе он не хранится, сбор текста вне рамок
  работы.

## Визуальные принципы

shadcn/ui (вариант Base UI, уже в `frontend/components/ui`) и минимализм:
`Table`, `ToggleGroup`, `Combobox` (добавить через `npx shadcn add combobox`),
`Popover`, `Badge`, `Tooltip`, `Empty`, `Skeleton`, `Alert`. Без графиков,
без цветовой радуги, одна строка фильтров.

## API

Новый эндпоинт `GET /api/v1/findings` (operation id `getFindings`):

| Параметр | Значения | По умолчанию |
|---|---|---|
| `mode` | `all`, `institution` | `all` |
| `institution` | UUID вуза; обязателен при `mode=institution` | — |
| `platform` | `all`, `telegram`, `vk`, `max`, `rutube` | `all` |
| `period` | `1d`, `7d`, `30d` | `7d` |
| `types` | повторяемый, тип публикации | все |
| `sort` | `interaction_index`, `view_index`, `interactions24`, `views24`, `erv24`, `published_at` | `interaction_index` |
| `direction` | `desc`, `asc` | `desc` |
| `group` | `none`, `institution` (только при `mode=all`) | `none` |
| `q` | до 200 символов | — |
| `limit`, `cursor` | как у текущих эндпоинтов | 50 |

Ответ: `items` (посты) или `groups` (вуз + до 3 постов + `findingCount`),
`hiddenAnomalous` (число исключённых постов уровня 2–3), `anomalyFilter`
(`applied` / `unavailable`), `nextCursor`, `datasetRevision`, `asOf`. Пост:
`publicationId`, `institutionId`, `institutionShortName`,
`institutionCanonicalName`, `accountId`, `platform`, `publicationType`,
`externalId`, `publicUrl`, `publishedAt`, `ageHours` (h),
`interactionIndex`, `viewIndex`, `interactionNorm`, `viewNorm`,
`normSampleSize`, `interactions`, `reactions`, `comments`, `shares`, `views`,
`erv` (всё на возрасте h), `currentInteractions`, `currentViews`,
`anomalyLevel` (NULL — не проверен), `capabilities`.

Ошибки (400): `period=3h` и другие неизвестные значения, `mode=institution`
без `institution`, `group=institution` при `mode=institution`, курсор чужой
ревизии или чужих параметров.

Реализация: `api/routes/findings.py`, `api/sql/findings.py`, DTO в `api/dto.py`,
нормализация в `api/params.py`. Кеш через `serve()` с тегами
`publications`, `catalog`, `findings`. Отдельной таблицы и миграции нет, если
`EXPLAIN ANALYZE` на проде укладывается в бюджет текущего `/statistics`; иначе
план предусматривает материализацию нормы аккаунта.

`/api/v1/statistics` помечается `deprecated: true` в OpenAPI и
`docs/REFERENCE.md` и продолжает работать; удаление — отдельная задача.

## Тесты

- `tests/test_findings.py`: эталонная реализация индекса на Python
  (по образцу `aggregate_statistics`), против которой сверяется SQL на
  фикстурах: предварительная точка у постов младше 24 ч; норма без уровней
  2–3 и без самого поста; recheck возвращает пост; меньше 10 постов → NULL;
  нижние ограничения 5 / 50; MAX — только реакции; порог ленты; группировка
  (3 поста, порядок вузов, пустые вузы скрыты); `hiddenAnomalous`. Плюс
  валидация параметров и курсоров.
- `frontend/tests/findings.test.ts`: нормализация URL-параметров, формат
  индекса (`×4,2`, «—», «предварительно»), выбор пометки по приоритету,
  группировка.
- Существующий browser-набор: десктоп и 375 px, тёмная тема, клавиатура в
  `Combobox` и `Popover`.

## Проверка на проде до плана

Только чтение, через мультиплексированное SSH-соединение, без изменений
сервисов: `EXPLAIN ANALYZE` нового SQL для `period=30d, platform=all` и
`mode=institution`; распределение числа прошедших порог постов по площадкам.
Адреса и доступы в репозиторий не записываются.
