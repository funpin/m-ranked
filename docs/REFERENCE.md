# Справочник продукта

Модель данных, формулы интерфейса и страницы, перенесённые из README.

## Модель данных новой версии

Telegram, VK, MAX и Rutube используют одну модель PostgreSQL:

| Сущность | Таблица |
| --- | --- |
| Вуз | `catalog.institution` |
| Аккаунт площадки | `catalog.platform_account` |
| Публикация | `ingest.publication` |
| Замер публикации | `ingest.publication_metric_snapshot` |
| Состав реакций | `ingest.reaction_breakdown` |
| Замер подписчиков | `ingest.account_metric_snapshot` |

Связи: вуз → аккаунты → публикации → замеры. Площадка определяется полем
`catalog.platform_account.platform`: `telegram`, `vk`, `max` или `rutube`.
Отдельных основных таблиц Telegram нет. Замеры публикаций разделены на месячные
партиции. Схема `analytics` содержит рассчитанные показатели, историю для
интерфейса и согласованную ревизию данных; `rating` — официальный рейтинг;
`ops_and_admin` — служебные данные; `migration` — доказательства переноса.
Next.js получает данные через Spring API и не обращается к БД напрямую.

У аккаунтов и публикаций общие UUID. Таблица `catalog.legacy_entity_alias`
сохраняет соответствие старых числовых ID этим UUID, отдельно для каждого
старого пространства имён, чтобы одинаковые номера не смешивались.

### Модель работающего legacy-релиза

В SQLite хранятся каналы, публикации и отдельные замеры. Медианы, приросты,
рейтинги и сравнение периодов не сохраняются отдельными агрегатами.

- Временные метки БД — UTC; интерфейс — Europe/Moscow.
- Пользовательский интерфейс показывает публикации за последние 70 дней.
- Telegram-публикации старше окна перед очисткой атомарно сохраняются в
  CSV.GZ. Платформенные снимки VK, MAX и Rutube пока остаются в SQLite.
- Уникальная пара `(post_id, measurement_bucket)` защищает от дублей.
- Пропущенные интервалы помечаются неопределёнными и не интерполируются.
- После изменения методики уже отслеживавшиеся публикации принудительно имеют
  статус «неполная история»: будущие замеры не превращают старую историю в
  полную задним числом.
- Удаление подтверждается двумя последовательными явными ответами Telegram
  `404/410`, `Post not found` или HTTP-200 заглушкой `Service message` вместо
  публикации; единичная ошибка только увеличивает счётчик.
- Временный нулевой сброс накопительного счётчика VK после положительного
  замера сохраняется как отсутствующее значение, а не как реальное падение.

## Формулы интерфейса

### Обзор

Периоды: 3 часа, сутки, 7 дней и 30 дней. Окно имеет форму
`(начало, конец]`: замер ровно на левой границе относится к предыдущему окну.

Для каждого поста любого возраста берутся первый и последний сопоставимые
замеры внутри окна. Для нового поста с полной историей началом служит
синтетический ноль в момент публикации.
Если этот baseline был сохранён в исходных данных до принудительной пометки
истории неполной, V30 сохраняет оба факта и прежний расчёт периода.

- `реакции/просмотры за период` — сумма приростов отдельных постов;
- `медиана прироста` — медиана приростов постов, округлённая до целого;
- цветная плашка — разница с предыдущим окном той же длины;
- плашка скрывается при нулевом изменении или отсутствии сравнения.

### Сравнение каналов

Для выбранного горизонта используются только публикации, история которых
покрывает его целиком. Поэтому состав выборки внутри одной линии постоянен.
На каждом целом часу используется последний замер, уже известный к этому часу:
будущий замер не переносится назад.

- накопление реакций — медиана накопленных реакций по фиксированной когорте;
- конверсия — сначала `реакции × 100 / просмотры` для каждого поста, затем
  медиана процентов по той же временной точке;
- tooltip каждой точки показывает число участвующих публикаций.

Одна Premium-реакция не равна одному человеку: Telegram позволяет одному
пользователю оставить несколько реакций.

## Страницы новой версии

- `/` — обзор активности каналов;
- `/rating` — рейтинг каналов и публикаций;
- `/compare` — накопление реакций и конверсия;
- `/accounts/{uuid}` — публикации и статистика аккаунта любой площадки;
- `/publications/{uuid}` — история публикации любой площадки;
- `/institutions/{id}?platform=...` — агрегированная страница вуза, если у него
  несколько аккаунтов выбранной площадки;
- `/manage` — управление, М‑Рейтинг и использование диска;
- `/export/snapshots.csv`, `/export/posts.csv` — экспорт;
- `/health` — состояние источника и метрики последнего цикла.

При одной выбранной площадке и единственном аккаунте страница вуза направляет
на `/accounts/{uuid}`; при нескольких аккаунтах показывает их вместе.
Старые `/channels/{id}`, `/platform-accounts/{id}`, `/posts/{id}` и
`/platform-posts/{id}` возвращают 308 на общий UUID-адрес, сохраняя параметры
просмотра. Внутренние ссылки ведут сразу на новые адреса.
API `/api/v1/accounts/{id}` и `/api/v1/publications/{id}`, включая списки
публикаций и историю, принимает UUID без `legacyType`. Числовые ID и
`legacyType` остаются для совместимости. Это поведение исходников новой версии;
production-переключение выполняется отдельно.

В истории замеров абсолютное значение каждой метрики расположено рядом с её
дельтой относительно предыдущего замера; все числовые дельты имеют явный знак
`+` или `−`. Заголовок компактной таблицы закреплён внутри области прокрутки,
а назначение иконок доступно при наведении и с клавиатуры.

Официальный М‑Рейтинг хранится на уровне вуза в пяти независимых срезах:
общий индекс соцсетей, Telegram, VK, MAX и RUTUBE. Команда
`sync-official-accounts` идемпотентно добавляет только вручную подтверждённые
официальные страницы. Для всех 24 вузов текущей выборки подтверждена хотя бы
одна страница VK, MAX или RUTUBE; если конкретная платформа не подтверждена,
её поле остаётся пустым.

## Несколько площадок

Проект развивается от мониторинга Telegram к модели «вуз → аккаунты социальных
сетей». Целевая схема, сопоставимые метрики и ограничения VK, MAX и Rutube
описаны в [docs/MULTIPLATFORM.md](docs/MULTIPLATFORM.md). Сырые показатели разных сетей
не считаются уникальным общим охватом.

В обзоре работает общий переключатель `Общий / TG / VK / MAX / RUTUBE`.
Выбранная площадка сохраняется в URL списков, фильтров, рейтинга, сравнения и
экспорта. Страницы конкретного канала, аккаунта и публикации определяют площадку
по своему ID и не требуют дублирующего query-параметра. Если у вуза один аккаунт
выбранной сети, карточка ведёт сразу на него; несколько аккаунтов раскрываются
на агрегированной странице вуза. Для VK/MAX/Rutube страницы и CSV читают только
снимки своей сети. Для VK также доступны отдельный рейтинг и
сравнение: вовлечённость считается как сумма лайков, комментариев и репостов,
делённая на просмотры, а кривые строятся на постоянной когорте публикаций. Для
Rutube рейтинг и сравнение используют публичные лайки, комментарии, просмотры,
вовлечённость и постоянную когорту видео; недоступные репосты не подменяются
нулями. Рейтинг и сравнение MAX пока показывают переходное состояние. Будущий режим «Общий»
станет сводкой по площадкам, а не суммой несопоставимых реакций.

Карточки обзора и страницы выбранного вуза/аккаунта используют один интерфейс
для TG, VK, MAX и Rutube: одинаковую сводку, счётчики публикаций и таблицу.
Различается только семантика площадки; недоступные показатели остаются `—`.

В исходной SQLite-схеме миграция 7 автоматически создаёт для каждого прежнего Telegram-канала
вуз и связанный `telegram`-аккаунт, не перемещая и не пересчитывая историю.
Миграция 8 добавляет платформенно-нейтральные таблицы публикаций и сырых
снимков. При заданном `VK_ACCESS_TOKEN` планировщик опрашивает привязанные
VK-сообщества и сохраняет просмотры, лайки, комментарии и репосты отдельно от
Telegram. Без токена VK-сбор не запускается и не влияет на основной цикл.
Идентификатор VK-публикации в интерфейсе всегда берётся со стены отслеживаемого
сообщества. Для совместной публикации дополнительно сохраняются исходный
идентификатор, признак совместной публикации и число дополнительных авторов.
MAX включается через отдельную пользовательскую сессию. При первом опросе
аккаунт подписывается на публичный канал по ссылке, после чего числовой
`chat_id` сохраняется автоматически. Снимки MAX используют ту же возрастную
сетку 5 / 15 / 30 / 60 минут, что Telegram и VK. Сборщик сохраняет просмотры,
общее число и состав реакций, доступный счётчик комментариев и каноническую
публичную ссылку поста; числовой счётчик репостов MAX пока недоступен. Rutube
использует официальные публичные API:
они дают просмотры, лайки и комментарии без токена, а недоступные репосты
сохраняются как `NULL`, не как ноль. Полный перечень секретов и прав — в
[docs/INTEGRATIONS.md](docs/INTEGRATIONS.md).

Миграция 11 добавляет признак исходящего репоста публикации. Для Telegram он
определяется по источнику пересылки, для MAX — по ссылке типа `forward` на другой
канал. Это отдельный признак публикации, а не числовой счётчик её репостов.
Миграция 12 очищает подтверждённые временные нулевые провалы VK, когда до и
после ошибочного ответа API сохранены положительные значения счётчика.
Миграция 15 достраивает публичные URL существующих публикаций MAX и помечает
их прежнюю историю неполной после расширения набора собираемых метрик.

В защищённой панели `/manage` можно создавать вуз и привязывать к нему аккаунты
Telegram, VK, MAX и Rutube. Существующие ссылки подставляются при выборе вуза;
сбор для любого аккаунта можно приостановить без потери истории или удалить
вместе с его данными. Интерфейс показывает состояние интеграции и не выдаёт
зарегистрированный аккаунт за уже работающий источник данных.
Полное и короткое названия вуза редактируются там же; в обзоре используется
короткое название, а полное доступно при наведении.

Проект ничего не публикует и не ставит реакции. Telegram-аккаунт не изменяется;
выделенный MAX-аккаунт при первом опросе автоматически вступает в настроенные
публичные каналы.
